02

Wire the emitter.

Use a transistor as a low-side switch. The Pi pin controls the gate; the LED current comes from the 5 V rail through a resistor. Keep the Pi powered off while wiring. Leave the A/C enclosure closed.

From To
Pi 5 V · physical pin 2 680 Ω → IR LED anode (+)
IR LED cathode (−) MOSFET drain (D)
BCM GPIO18 · physical pin 12 100 Ω → MOSFET gate (G)
MOSFET gate (G) 100 kΩ → ground (pull-down)
MOSFET source (S) Pi GND · physical pin 6; same ground as pull-down

Identify first, then apply power

Use a multimeter diode test to identify the emitter’s polarity and forward voltage. Salvaged legs may have been cut, so lead length is unreliable. Verify the MOSFET’s actual manufacturer and pinout. Wire labels in the diagram do not specify left-to-right TO-92 legs.

At 5 V, a provisional LED drop of 1.2–1.5 V gives about 5–6 mA through 680 Ω, before transistor losses. This is a conservative starting point, not a proven rating for the Yamaha LED. Measure voltage across the resistor: current is I = Vresistor / 680 Ω. A meter averages bursts; it cannot measure peak pulse current from this reading.

Calculation: I = (Vsupply − VLED − Vswitch) / R. A 330 Ω resistor would give roughly 10–12 mA under the same assumptions. Do not increase current based only on a weak camera image. No 100 mA pulse drive is justified without the emitter’s own datasheet.

Pin check: GPIO18 was free at inspection. GPIO17 is owned by the alert light, GPIO14 by the fan, and GPIO23/24 by software I²C. Recheck before installing the IR overlay. Pin numbers here refer to the 40-pin header.

03

Set up the Pi.

The guide server and API can run before the circuit exists. Hardware setup is a separate, deliberate step. These commands run in your Terminal; the guide never edits boot configuration from the browser.

  1. Inspect the project

    ssh pi@vanpi.lan
cd /home/pi/visual-guides/current
python3 hardware_setup.py status
python3 app.py --preview temp_up

    Preview returns the waveform without opening a LIRC device. The Pi already had /usr/bin/ir-ctl at inspection.

  2. Assemble, inspect, and configure

    Power the Pi down before attaching wires. After the circuit is checked and the Pi is running again, reconnect and use the setup helper: 

    python3 hardware_setup.py configure --confirm-wiring

    The helper checks GPIO18 ownership, backs up the boot configuration, and installs the gpio-ir-tx overlay line plus a dedicated udev device alias. It does not send IR or reboot. The overlay uses BCM numbering: dtoverlay=gpio-ir-tx,gpio_pin=18.

  3. Reboot when the van’s services can pause

    Finish any backup or other active Pi work first. Rebooting interrupts all services, not just this guide. 

    sudo reboot

    Reconnect after the Pi returns:

    ssh pi@vanpi.lan
cd /home/pi/visual-guides/current
python3 hardware_setup.py status

    Check that /dev/van-ac-ir-tx resolves to a transmitter. Never assume /dev/lirc0 stays assigned to the same device when adding a receiver.

  4. Enable transmissions, then aim and test

    python3 hardware_setup.py activate --confirm-wiring

    Activation validates the driver and transmit capability, then restarts only the guide service with hardware enabled. It does not transmit. Start with one temperature-up command while the A/C is already on, at a midrange temperature setting. Observe its display and beep. Power is a toggle; repeated tests can undo each other.

    Use the first-test handoff below from your Mac. It sends one temperature-up command through the local API and does not retry. A successful response does not confirm reception.

  5. Return to preview mode any time

    python3 hardware_setup.py deactivate

    This turns off API transmission while keeping the guide available. It leaves the boot overlay installed. Never remove or repurpose the hardware while a transmitter service is active.

Short Terminal handoffs

From the Mac, use the prepared first-test script after hardware activation. Its contents are visible in first-test.txt. To place the private browser token on your Mac’s clipboard, use the copy-token.txt script. Neither script embeds a token.

On this Mac, run zsh /tmp/clip/ac-ir-test-2251 for the first send, or zsh /tmp/clip/ac-ir-token-2251 to copy the token. These temporary files may disappear after a restart. The linked scripts are their exact contents; save them if needed. CLI sends share the API’s admission lock, so they cannot overlap browser transmissions.

05

The language on the wire.

The emitter is just a light source; it does not retain Yamaha’s protocol. Linux’s gpio-ir-tx driver generates the carrier and pulse timing through ir-ctl. Python chooses a reviewed waveform instead of bit-banging timing with sleeps.

One tap, 32 bits

38 kHz carrier. Measured leader: 9,159 µs on / 4,455 µs off. A bit is a 639 µs mark, followed by 486 µs for 0 or 1,615 µs for 1. Finish with a 637 µs mark. No held-key repeats.

These are the measured Kenmore profile’s timings, not exact measurements from your Frigidaire.

Bit order matters

Legacy LIRC displays 10 AF CC ~CC in MSB order. The equivalent logical NEC bytes are 08 F5 reverse8(CC) ~reverse8(CC), each sent LSB first.

For temperature up: LIRC 10AF708F → Linux necx:0x08f50e. Sending the printed legacy value directly as a Linux scancode reverses the bits incorrectly.

The API sends raw measured timings. Linux scancodes above describe the equivalent bits using the standard encoder. All entries remain compatibility candidates until observed working on this A/C. Timer and sleep need extra validation; their state is not tracked.

API contract

Request Result
GET /api/health Service health, no hardware action
GET /api/ac/status Hardware permission mode; A/C state always unknown
GET /api/ac/commands Canonical commands, source notes, carrier and pulses
POST /api/ac/commands/temp_up {"preview":true} gives a dry run; {"preview":false} requires hardware mode plus Authorization: Bearer …

POST bodies must be JSON with exactly one boolean preview field. Commands are serialized, rate-limited, and never automatically retried. 202 means transmitted but unconfirmed; 409 means hardware is disabled; 401 is a missing/invalid token; 429 means wait before another tap. A transmission error is ambiguous: inspect the A/C before retrying.

No absolute temperature, power-on, or power-off endpoint is provided: this command set has relative adjustments and a power toggle, with no feedback. “Cool mode / start” may also start the unit.

Private access over SSH

ssh -N -L 8792:127.0.0.1:8791 pi@vanpi.lan

Keep that Terminal open, then visit localhost:8792. Tokens and commands travel through SSH. The normal LAN endpoint uses HTTP, so avoid sending a bearer token over an untrusted network.

06

When nothing happens.

No device / permission denied

Run python3 hardware_setup.py status. The overlay needs a reboot after configuration. Check the stable alias, gpio-ir-tx driver, udev rule and transmitter capabilities before changing permissions.

Do not make every LIRC device world-writable.

IR is visible, A/C ignores it

Move close, aim at the front receiver and avoid bright sunlight. Check LED polarity, wiring and MOSFET drive. Try one temperature step while the A/C is on. A camera can reveal some IR emission but cannot verify the carrier or bits.

Unsure whether a send worked

Look at the physical A/C display. An HTTP success only confirms that the transmit process completed. A timeout may happen after emission started. Do not blindly repeat power or timer commands.

Every command is ignored

Verify the optical waveform with a 38 kHz receiver. If the candidate profile is incompatible, obtain or borrow the exact replacement remote 5304487535 and capture its commands. Replace the canonical profile only after comparing real captures.

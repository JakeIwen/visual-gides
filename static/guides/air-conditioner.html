Get or confirm you have

  • Resistors, ¼ W: 680 Ω (LED), 100 Ω (gate), 100 kΩ (gate pull-down). Optionally 330 Ω for a later, measured current step.
  • Multimeter with diode test, to find the LED's polarity and forward drop.
  • Soldering iron and solder, plus heat-shrink or other insulation.

None of these are in the catalog. That doesn't mean you don't own them.

Optional

  • A solderless breadboard for a first trial.
  • A 38 kHz demodulating IR receiver such as TSOP38438, to check the transmitted waveform.
  • A documented IR LED, if the donor can't be identified or tested.
  • A MOSFET rated for 2.5–3.3 V gate drive, or a verified NPN driver, if the 2N7000 switches poorly. Its on-resistance isn't guaranteed at 3.3 V.

Wiring

The MOSFET switches the LED's low side. GPIO18 only drives the gate; LED current comes from the 5 V pin through the 680 Ω resistor. Keep the Pi powered off while wiring, and leave the A/C's enclosure closed.

Pins 1–12 of the 40-pin header, drawn with pin 1 at the left. All three wires land in the even-numbered row, on the 1st, 3rd and 6th pins from the pin-1 end. Find pin 1 on the board before connecting anything.

Identify the parts before applying power

  • LED: use the meter's diode test to find polarity and forward drop. Salvaged legs may have been trimmed, so lead length tells you nothing.
  • MOSFET: confirm the actual manufacturer and its pinout. The D/G/S labels in the schematic are electrical pins, not TO-92 leg order.

LED current

I = (Vsupply − VLED − Vswitch) / R. With a provisional 1.2–1.5 V LED drop, 680 Ω gives about 5–6 mA before transistor losses; 330 Ω would give about 10–12 mA. That's a conservative start, not a rating for the Yamaha LED.

A meter averages the bursts, so this isn't peak pulse current.

  • Never connect the LED straight to a GPIO pin, and never leave out its series resistor.
  • Don't raise the current because a phone camera shows a weak glow. No 100 mA pulse drive is justified without the emitter's own datasheet.

GPIO availability

GPIO18 was free at the last inspection. Already taken: GPIO17 (alert light), GPIO14 (fan), GPIO23 and GPIO24 (software I²C). hardware_setup.py rechecks GPIO18's owner before changing anything.

Pi setup

Run these in your own Terminal, over SSH as pi. The helper calls sudo only for its fixed boot, udev and systemd writes, and refuses to run under sudo itself. Nothing here is done from the browser. The guide and API already run without the circuit.

Tick steps off as you go; ticks stay in this browser only.

  1. 1

    Check the Pi (read-only)

    ssh pi@vanpi.lan
cd /home/pi/visual-guides/current
python3 hardware_setup.py status
python3 hardware_setup.py prepare
python3 app.py --preview temp_up

    status and prepare only read; prepare adds ready_to_configure. --preview prints the waveform without opening any IR device. /usr/bin/ir-ctl was already installed at inspection.

  2. 2

    Build the circuit with the Pi off

    Shut down when the van's Pi services can pause, then remove power:

    sudo poweroff

    Identify the LED and MOSFET pins, build the circuit, check it against the connection table, then power the Pi back on.

  3. 3

    Install the boot overlay and device rule

    ssh pi@vanpi.lan
cd /home/pi/visual-guides/current
python3 hardware_setup.py configure --confirm-wiring

    --confirm-wiring is your statement that the circuit is on GPIO18, physical pin 12. The helper:

    • backs up the active boot config byte-for-byte to ~/.local/state/visual-guides/;
    • adds a managed block with dtoverlay=gpio-ir-tx,gpio_pin=18 (BCM numbering);
    • installs /etc/udev/rules.d/70-visual-guides-ir-tx.rules, which names the transmitter /dev/van-ac-ir-tx.

    It refuses if another owner holds GPIO18, a conflicting overlay exists, or a managed file has foreign contents. It doesn't load the overlay live, reboot or send IR.

  4. 4

    Reboot, then check the device

    Finish backups and other active Pi work first: a reboot stops every service on the Pi, not just this one.

    sudo reboot

    Once it's back:

    ssh pi@vanpi.lan
cd /home/pi/visual-guides/current
python3 hardware_setup.py status

    Expect /dev/van-ac-ir-tx to resolve to a LIRC device owned by the gpio-ir-tx driver. Don't rely on /dev/lirc0: numbering can change once a receiver is added.

  5. 5

    Turn on transmission

    python3 hardware_setup.py activate --confirm-wiring

    Checks that gpio-ir-tx owns GPIO18 and that the device can transmit but not receive, installs the hardware drop-in for visual-guides.service, restarts only that service and waits for it to report hardware enabled. It sends nothing. If the service doesn't come back healthy, a newly installed drop-in is removed and preview mode is restored.

  6. 6

    Send one temperature-up

    Have the A/C already running at a midrange setting with its display visible. Hold the LED close to the front receiver, out of bright sun. Send exactly one command and watch for the display change and beep. On the Pi:

    cd /home/pi/visual-guides/current
python3 app.py --enable-hardware --send temp_up \
  --token-file /home/pi/.config/visual-guides/api-token

    Or from the Mac, with the first-test script, which runs the same command over SSH. Download it and read it:

    mkdir -p -m 700 /tmp/clip
curl -so /tmp/clip/ac-first-test http://vanpi.lan:8791/first-test.txt
cat /tmp/clip/ac-first-test

    Then run it:

    zsh /tmp/clip/ac-first-test

    Either way the send goes through the running service's API, so it can't overlap a browser send. It is never retried. "delivery": "transmitted" means ir-ctl finished, not that the A/C heard it; confirmed is always false.

  7. 7

    Test the rest, one at a time

    Next temp_down, then each other command you need, one at a time, noting what the A/C does. Swap the name in the step 6 command; python3 app.py --list-commands lists them.

    • Power is a toggle. Two sends undo each other.
    • Cool mode / start may also start the unit.
    • Timer and sleep need extra care; their state isn't tracked.
    • A failed or timed-out send may still have emitted. Check the display before repeating.
  8. 8

    Return to preview mode

    python3 hardware_setup.py deactivate

    Removes the hardware drop-in and restarts the service in preview mode; the guide stays up and the boot overlay stays installed. Do this before you disconnect or repurpose the circuit.

Protocol

The LED is only a light source; nothing of Yamaha's protocol carries over. The Linux gpio-ir-tx driver makes the 38 kHz carrier, and ir-ctl plays a reviewed raw waveform from the catalog. Python doesn't time pulses with sleeps.

Bit order

Legacy LIRC files print the frame MSB-first: 10 AF, then each command byte bit-reversed. Linux's NECX scancode uses the logical bytes 08 F5 cmd. Temperature up is LIRC 10AF708F = Linux necx:0x08f50e. Handing the LIRC value to Linux unchanged reverses every bit.

API

RequestReturns
GET /api/health{"ok":true,"service":"visual-guides"}
GET /api/ac/statushardware_enabled, ac_state (always "unknown"), state_note
GET /api/ac/commandsThe catalog: name, label, carrier, durations, Linux scancode, sources
POST /api/ac/commands/<name>{"preview":true} returns a dry run. {"preview":false} transmits, and needs hardware mode plus a bearer token.
  • POSTs need Content-Type: application/json and a body of exactly one boolean preview field, 256 bytes at most.
  • Previews need no token. Real sends need Authorization: Bearer … and a same-origin request; scripts may omit Origin.
  • Real sends are serialized and never retried, with a 1-second cooldown after every attempt, failures included.
  • delivery is dry_run or transmitted; confirmed is always false. No A/C state is inferred.

Tokens and untrusted networks

The token lives only in /home/pi/.config/visual-guides/api-token (mode 0600). It is never in static files, API responses, command arguments or deploy logs. The LAN endpoint is plain HTTP, so on a network you don't trust, tunnel over SSH and keep that Terminal open:

ssh -N -L 8791:127.0.0.1:8791 pi@vanpi.lan

Then use http://localhost:8791.

Troubleshooting

No device, or permission denied
Run python3 hardware_setup.py status. The overlay needs a reboot after configure. Check the /dev/van-ac-ir-tx alias, the gpio-ir-tx driver, the udev rule and transmit capability before touching permissions. Don't make LIRC devices world-writable.
HTTP 409 on a real send
The service is still in preview mode. Run step 5.
A camera shows the LED, but the A/C ignores it
Get closer, aim at the front receiver and avoid bright sun. Check LED polarity, wiring and MOSFET drive. Try a single temperature step with the A/C on. A camera shows some IR light but can't check the carrier or the bits.
Not sure a send worked
Look at the A/C's display. An HTTP success only means ir-ctl finished, and a timeout can happen after emission started. Don't blindly repeat power or timer.
Every command is ignored
Check the optical waveform with a 38 kHz receiver. If the profile doesn't fit this unit, get or borrow the exact replacement remote, 5304487535, and capture its commands. Replace the catalog in ac_ir.py only after comparing real captures.

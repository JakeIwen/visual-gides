Remote BME280 climate sensor

Use
Temperature, humidity and pressure from the far side of the van, shown in Home Assistant beside the Pi's own BME280.
Node
HiLetgo NodeMCU ESP8266 running ESPHome, BME280 on I²C (D1/D2), powered by 5 V USB.
Link
Wi-Fi to dendelion, then MQTT to Mosquitto on vanpi, port 1884 with a password. No cable to the Pi.
Pi changes
One Mosquitto config file and a password file. Home Assistant and bme280-mqtt stay as they are.
Status
Not built Configs written against ESPHome 2026.9 and Mosquitto 2.0.11; nothing flashed or applied yet.
Updated
2026-10-13

How it fits

Inspected 2026-10-13: Home Assistant Core 2024.3.3 on vanpi already has the MQTT integration (broker 127.0.0.1:1883, discovery on). bme280-mqtt is publishing vanpi/sensors/vanpi_bme280_1 from a BME280 on GPIO23/24, humidity included. Mosquitto listens only on 127.0.0.1:1883, so a node on Wi-Fi can't reach it yet. Step 1 adds a password-protected LAN listener.

Wiring

Four wires, all at 3.3 V. Unplug USB while wiring.

Connections

NodeMCUWireBME280
3V3female–femaleVIN
GNDfemale–femaleGND
D1 (GPIO5)female–femaleSCL
D2 (GPIO4)female–femaleSDA

On the usual NodeMCU 1.0 layout, D1, D2, 3V3 and GND are all on the D0–D8 row: 2nd, 3rd, 6th and 7th pins from the D0 end. Go by the silkscreen on your board, not this count.

If you use the 6-pin HiLetgo board instead

  • VCC → 3V3, GND → GND, SCL → D1, SDA → D2.
  • CSB → 3V3 to keep it in I²C mode. ESPHome's docs recommend this to avoid communication failures.
  • SDO → GND for address 0x76 (matches the config), or 3V3 for 0x77. Don't leave it floating.

Power

The node draws well under 100 mA at 5 V, with short Wi-Fi peaks. Any 5 V USB outlet already on that side of the van is the simplest supply. Otherwise use the CPT buck:

  1. Take 12 V from a fused house-battery branch, or add the inline fuse holder (2–3 A) right at the tap. Red is + and black is −, per the label. Check with the meter before the first connection.
  2. With nothing plugged in, meter the USB-A socket: pins 1 (+) and 4 (−), the outer two. Expect close to 5.0 V.
  3. Plug the NodeMCU in with the data cable. Use its micro-USB port, not the VIN pin.
  • The CPT label says 12 V and gives no input range or surge rating. Prefer a house-battery circuit over anything tied to the alternator or ignition.
  • Rough always-on draw: about 0.5 W including converter loss, roughly 1 Ah a day at 12 V. That's an estimate, not a measurement.

Step 1 · Pi: open the broker

This adds a LAN listener on 1884 that requires a password. Port 1883 stays loopback-only and anonymous, so Home Assistant and bme280-mqtt keep working unchanged. Run it in your own Terminal, after the guide has been deployed to the Pi (npm run deploy), so the reference file below exists.

ssh pi@vanpi.lan
sudo cp /home/pi/visual-guides/current/static/reference/remote-bme280-mosquitto.conf.txt \
  /etc/mosquitto/conf.d/lan-sensors.conf
openssl rand -base64 18
sudo mosquitto_passwd -c /etc/mosquitto/passwd van-climate-rear
sudo chown root:mosquitto /etc/mosquitto/passwd
sudo chmod 640 /etc/mosquitto/passwd
sudo systemctl restart mosquitto
systemctl is-active mosquitto home-assistant bme280-mqtt
ss -ltn | grep -E ':188[34]'

Paste the openssl output at the mosquitto_passwd prompt (twice) and keep it for secrets.yaml in step 2. -c creates the file; leave it off when adding a second sensor later, or it wipes the first. ss should show 127.0.0.1:1883 and *:1884.

Check that the existing sensor still updates (Ctrl-C to stop):

mosquitto_sub -h 127.0.0.1 -t 'vanpi/sensors/#' -v

The config file is remote-bme280-mosquitto.conf.txt. To undo: sudo rm /etc/mosquitto/conf.d/lan-sensors.conf && sudo systemctl restart mosquitto. Port 1884 is also reachable over Tailscale. It's password-protected, but there's no per-topic ACL.

Step 2 · Mac: flash the node

Install ESPHome and fetch the config

brew install esphome
mkdir -p ~/esphome && cd ~/esphome
curl -fsS http://127.0.0.1:8792/reference/remote-bme280-esphome.yaml.txt -o van-climate-rear.yaml
curl -fsS http://127.0.0.1:8792/reference/remote-bme280-secrets.example.yaml.txt -o secrets.yaml
chmod 600 secrets.yaml
open -e secrets.yaml

Fill in the dendelion Wi-Fi password and the MQTT password from step 1. Make up the OTA and fallback-hotspot passwords with openssl rand -base64 18. Keep ~/esphome out of any Git repo.

The files are remote-bme280-esphome.yaml.txt and remote-bme280-secrets.example.yaml.txt. Homebrew had ESPHome 2026.9.1 on 2026-10-13.

First flash over USB

Wire the sensor first, then plug the board into the Mac and find its port:

ls /dev/cu.*
esphome run van-climate-rear.yaml --device /dev/cu.usbserial-XXXX

Use whichever new cu.usbserial-… or cu.SLAB_USBtoUART entry appeared. The first compile takes several minutes. After uploading, run streams the serial log. Look for:

  • Found i2c device at address 0x76. If it says 0x77, change address: in the YAML and run again.
  • The Wi-Fi connected and MQTT connected lines.
  • Temperature, pressure and humidity values about once a minute, with no BME280 error.

If no new port appears, try another cable first (see Troubleshooting). Ctrl-C stops the log, not the node.

Later updates over Wi-Fi

cd ~/esphome
esphome run van-climate-rear.yaml --device van-climate-rear.local

OTA uses the ota_password. If .local doesn't resolve, use the IP shown in the router's DHCP leases.

Step 3 · Home Assistant

Nothing to configure. Discovery adds a device named Van climate rear with Temperature, Humidity, Pressure and Wi-Fi signal sensors. Find it under Settings → Devices & services → MQTT. Check the raw messages on the Pi:

mosquitto_sub -h 127.0.0.1 -t 'vanpi/sensors/van_climate_rear/#' -v
TopicPayload
vanpi/sensors/van_climate_rear/statusonline, retained. The broker sets offline when the node drops off.
…/sensor/temperature/state°C
…/sensor/humidity/state% RH
…/sensor/pressure/statehPa
…/sensor/wi-fi_signal/statedBm. Below about −80 means the node needs a better spot.

The Pi sensor publishes one JSON object; this node publishes one topic per value. Both are under vanpi/sensors/, and Home Assistant treats them the same way.

Placement and accuracy

  • Keep the sensor out of the box. A sealed IP65 box blocks humidity exchange and traps the ESP8266's heat. Run the four leads through a small hole in the box's bottom face and let the sensor hang 10 cm or more below it, port facing the room.
  • Below, not above. Warm air from the board and buck rises. Keep both above the sensor or off to one side.
  • Not on an outside wall panel, in sun through a window, near the heater or fridge vent, or in cooking steam. Those are worth measuring separately, not by accident.
  • Low oversampling and a 60 s interval keep the sensor from heating itself. Shortening the interval raises the reading.
  • Calibrate against the Pi sensor. Put both side by side for 30 minutes, then add an offset to the node's temperature if the two differ consistently:
    temperature:
      name: Temperature
      oversampling: 1x
      filters:
        - offset: -0.5

Pressure tracks weather and altitude, not van climate. Both sensors should agree within about 1 hPa. A larger gap points to a faulty sensor, not placement.

Troubleshooting

SymptomFix
No new /dev/cu.* portCharge-only cable; try the data cable. Then try another USB port or hub. Still nothing: install the Silicon Labs CP210x VCP driver.
Upload times out at “Connecting…”Hold FLASH, tap RST, release FLASH, and run again. Unplug anything on D3, D4 or D8.
I²C scan finds nothingSDA/SCL swapped, sensor on 5 V instead of 3V3, or a loose Dupont end. On the 6-pin board, check CSB and SDO.
Wrong chip ID or no response while the scan does find 0x76/0x77Most likely a BMP280 (no humidity). Change the platform to bmp280_i2c and delete the humidity block, or fit a real BME280.
Wi-Fi never connects, fallback hotspot appearsWrong SSID or password in secrets.yaml. Join the hotspot from a phone and enter it there, or reflash over USB. If other new devices can't join dendelion either, the router has the known SAE association fault: run wifi down radio0; wifi up radio0 on the router.
Wi-Fi connects, MQTT doesn'tOn the Pi: ss -ltn | grep 1884 and sudo tail /var/log/mosquitto/mosquitto.log. “not authorised” means the password in secrets.yaml doesn't match mosquitto_passwd.
Messages on the broker but no device in Home AssistantCheck the MQTT integration is still connected (Settings → Devices & services → MQTT), then restart Home Assistant once to resend discovery.

Why not wire it to the Pi

I²C is meant for a single board. Across a van, cable capacitance runs past the bus's 400 pF limit, and the Pi's BME280 already uses its software I²C bus on GPIO23/24. A cable run would need a differential I²C extender at each end (PCA9615-type) and a cable routed through the walls, which is more parts than the Wi-Fi node and still adds a fault path into the Pi's GPIO.

Other routesTrade-off
ESPHome native API instead of MQTTNeeds the ESPHome integration added to Home Assistant 2024.3, about two and a half years older than current ESPHome firmware. MQTT works with both versions and leaves the broker as the single path.
Off-the-shelf BLE thermometerNo wiring or power work, but it doesn't use the BME280 or give you pressure.
ideaspark ESP32 or ESP8266 OLED boardAlso in the inventory and could show the reading locally. But the display pin routing is unverified, and the extra heat sits closer to the sensor.

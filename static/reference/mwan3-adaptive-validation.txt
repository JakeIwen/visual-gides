# 0.2.0-r1 candidate validation

This is an unpublished review candidate. These results are evidence for the
tested configurations, not certification for every OpenWrt release or router.

## Checks performed

| Check | Result and scope |
|---|---|
| Portable suite | Passed with Lua 5.4 on macOS and Lua 5.1 on Linux; 17 algorithm, parser, and ownership cases plus shell probe tests |
| Configuration export | Valid selected policies remain usable with unrelated invalid policies; explicitly selected invalid configuration is rejected |
| Controller and recovery | CLI compatibility check, observation, learning, application, status, static restoration, failures before/after commit, unknown-layout refusal and snapshot cleanup passed |
| Init lifecycle | Disabled/duplicate/fenced starts, residual recovery, propagated start failures, restart/reload failure gates passed |
| Kernel transactions | Real IPv4 new-flow distribution and established connection marks passed with iptables-nft 1.8.9; preflight rejection, later-family compensation, rollback failure and unrelated-rule preservation passed |
| Upstream contract | Real policy chains generated by hash-pinned mwan3 2.12.2 passed: equal/skewed weights, zero rounded probabilities, failover tiers, offline/last-resort chains and alternate masks |
| Backend coverage | Upstream IPv4 generation tested through both legacy and nft APIs; IPv6 generation/transactions tested through nft |
| Package build | Native OpenWrt package machinery produced an architecture-independent IPK; 14 installed files, modes, ownership, maintainer, dependencies, version and removal hook verified against the source |
| OpenWrt userspace | Built-payload smoke passed in isolated OpenWrt 24.10.4 ARM64 userspace with its official Lua 5.1 packages; private runtime-directory preparation and rejection of unsafe permissions passed |
| Removal hook | Generated hook returns failure when service stop fails, succeeds after a successful stop, and skips live actions during offline-image construction |
| HTML guide | Command generation, policy validation, scenarios, desktop/mobile layout and browser script execution passed |

The Linux kernel test host used `6.12.62+rpt-rpi-v8`. IPv6 sockets were disabled
on that kernel: IPv6 packet-flow testing was explicitly skipped, independently
of the successful IPv6 rule tests. A full legacy IPv6 traffic test was not
performed. The CI workflow includes both command APIs for environments with the
necessary kernel support; the workflow itself has not been published or run on
GitHub as part of this candidate preparation.

No production router deployment, radio throughput benchmark, broad hardware
matrix or formal upstream review was performed. Maintainer review and
representative router testing are required before publication.

## Reproduce

The commands and prerequisites are in the package README and CONTRIBUTING.md.
`tests/run.sh` separates portable, Linux CLI, and privileged namespace suites.
For Linux checks outside this repository, set `OPENWRT_ROOT` to an OpenWrt source
checkout so the tests can use its actual shell configuration helpers.

The upstream harness pins revision
`6fb711fed018a04030ffae4976030b7079c9a489` of `openwrt/packages` and verifies
SHA-256 hashes before executing any upstream code. Fetch the sources first;
`run` requires a fresh, isolated namespace and does not download anything.
The package-root `test.sh` is an installed-payload smoke for the packages feed.

The candidate IPK contains no device-specific network configuration. Its source
is bundled under `files/`; a separate upstream source archive is optional for
this packaging model. Consult RELEASING.md for the publication gates.
